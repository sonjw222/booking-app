# UI / UX

## 1. 경험 원칙

- 고객 예약은 모바일 우선, 최소 단계, 명확한 진행 상태를 제공한다.
- 권한이 없는 기능은 숨기되 직접 URL 접근은 서버가 다시 차단한다.
- 파괴적 동작은 대상·영향을 명시하고 확인을 받는다.
- 오류는 사용자가 복구할 수 있는 다음 행동과 함께 보여준다.
- 시간은 센터 시간대로 표시하고 다른 시간대 사용자는 이를 명확히 인지할 수 있어야 한다.
- WCAG 2.2 AA를 목표로 키보드, 포커스, 명도 대비, 오류 연결, 스크린리더 레이블을 지원한다.

## 2. 정보 구조

### 고객

`센터 선택 → 서비스 선택 → 직원(선택) → 날짜/시간 → 고객 정보 → 검토/확정 → 완료`

- 슬롯 만료/충돌 시 입력을 보존하고 가장 가까운 대체 시간을 제시한다.
- 완료 화면은 센터, 서비스, 현지 날짜/시간, 직원, 예약 상태, 변경/취소 방법을 표시한다.
- 로그인 사용자는 내 예약과 계정/보안 설정에 접근한다.

### 센터 운영자

- 대시보드
- 예약: 캘린더/목록/상세
- 서비스
- 직원 및 근무 일정
- 고객
- 센터 설정
- 구성원·초대·권한
- 감사 로그
- 내 계정·보안·기기

센터 선택기는 헤더의 지속적인 위치에 두고 현재 센터 이름을 항상 표시한다. 센터 전환 시 필터와 선택 상태를 초기화하여 다른 센터 정보가 화면에 남지 않게 한다.

### 플랫폼 운영자

센터와 사용자 상태, 지원용 감사 정보만 별도 콘솔에서 제공한다. 센터 데이터 가장(impersonation)은 v1 기본 범위가 아니며 도입 시 명시적 배너, 사유 입력, 제한 시간, 감사 로그가 필요하다.

## 3. 인증 화면

### 가입과 로그인

- 이메일/비밀번호와 활성화된 소셜 공급자를 동일 화면에서 제공한다.
- 이메일 중복 여부를 가입 폼에서 과도하게 노출하지 않는다.
- 이메일 미인증 사용자는 재전송과 이메일 변경 경로를 제공한다.
- 로그인 실패는 계정 존재/정지 여부를 공격자에게 구분해 주지 않는 일반 문구를 사용한다.

### Account Linking

소셜 로그인 이메일이 기존 계정과 충돌하면 다음을 안내한다.

1. 기존 방식으로 로그인하여 본인임을 확인한다.
2. 연결하려는 소셜 계정을 다시 인증한다.
3. 연결될 로그인 수단을 검토하고 확정한다.

자동 병합이나 “계속” 한 번으로 연결하지 않는다. 연결 해제 화면은 남는 로그인 수단을 보여주고 마지막 수단 삭제를 차단한다.

### 비밀번호 찾기

- 이메일 입력 후 계정 존재 여부와 관계없이 같은 완료 화면을 표시한다.
- 재설정 링크가 만료·사용됨·잘못됨인 경우 새 링크 요청 동선을 제공한다.
- 성공 후 기존 기기에서 로그아웃되었음을 알리고 다시 로그인하게 한다.

## 4. 관리자 초대

초대 작성 화면은 이메일, 역할, 권한 요약, 만료일을 보여준다. 전송 전 “이 사용자는 현재 센터에 접근하게 된다”는 범위를 명시한다.

초대 목록에는 상태, 이메일, 역할, 초대한 사람, 전송/만료 시각과 재전송·취소 행동을 제공한다. 토큰은 UI나 URL 이외의 로그/분석에 보내지 않는다.

수락 화면은 센터명, 초대 역할, 초대 이메일을 마스킹해 표시한다.

- 미로그인: 가입 또는 로그인 후 계속
- 다른 이메일로 로그인: 계정 전환 안내
- 만료/취소: 관리자에게 새 초대 요청
- 이미 수락: 해당 센터로 이동

## 5. 세션과 기기 관리

보안 설정에서 다음을 제공한다.

- 현재 기기 강조
- 기기명/플랫폼, 최근 활동 시각, 대략적 위치(정확하지 않을 수 있음)
- 기기별 로그아웃
- “다른 모든 기기에서 로그아웃”
- 비밀번호 변경, 연결된 로그인 수단
- 최근 보안 활동

철회한 현재 세션은 즉시 로그인 화면으로 이동한다. 낯선 기기 신고는 해당 세션 철회와 비밀번호 변경/소셜 계정 점검을 안내한다.

## 6. 상태와 피드백

- 로딩: 레이아웃 이동을 줄이는 skeleton 또는 진행 표시
- 빈 상태: 이유와 다음 행동
- 저장: 중복 제출 방지, 진행 상태, 완료 피드백
- 오류: 필드 인접 오류 + 상단 요약, 최초 오류로 포커스 이동
- 위험 동작: 센터/사용자/예약 등 대상명 재확인
- 알림과 토스트만으로 중요한 결과를 전달하지 않는다.

## 7. 반응형 및 접근성 수용 기준

- 320 CSS px 폭에서도 고객 예약 완료 가능
- 키보드만으로 모든 핵심 작업 완료
- 모달 포커스 고정/복귀, ESC 동작 일관성
- 색상만으로 상태를 구분하지 않음
- 입력 `label`, 오류 `aria-describedby`, 동적 상태 live region 적용
- 날짜/시간 선택기에 텍스트 대안 제공
- 브라우저 확대 200%에서 콘텐츠/기능 손실 없음
