# Claude Rules

> 이 파일은 Claude를 포함한 AI 코딩 에이전트가 Booking App을 변경할 때 따라야 할 프로젝트 규칙이다. 저장소의 상위 `AGENTS.md` 또는 시스템 지침이 충돌하면 더 높은 우선순위의 지침을 따른다.

## 1. 작업 시작

1. `docs/00_Project_Principles.md`와 변경 영역 문서를 먼저 읽는다.
2. 요구사항을 임의로 확장하지 않는다. 미확정 기술 선택은 `08_Decision_Log.md`에서 확인한다.
3. 현재 구현, 테스트, 마이그레이션, 작업 트리 상태를 확인한다.
4. `sources/`가 존재하면 읽기 전용으로 취급하며 수정·이동·삭제하지 않는다.
5. 관련 없는 사용자 변경을 되돌리거나 정리하지 않는다.

## 2. 절대 규칙

- 인증 성공을 권한 승인으로 간주하지 않는다.
- 센터 소유 데이터는 반드시 검증된 `center_id` 범위에서 읽고 쓴다.
- 클라이언트가 보낸 `center_id`, role, user ID를 권한 근거로 신뢰하지 않는다.
- 권한 검사는 UI가 아니라 서버에서 수행한다.
- ID만 받는 센터 엔티티 저장소 API를 새로 만들지 않는다.
- 이메일 일치만으로 계정이나 소셜 identity를 병합하지 않는다.
- 비밀번호, Access/Refresh Token, 초대·인증·재설정 토큰 원문을 저장하거나 로그에 남기지 않는다.
- 마지막 Center Owner를 제거/강등할 수 있게 만들지 않는다.
- 예약 중복을 사전 조회만으로 막지 않는다. DB 트랜잭션/제약을 포함한다.
- 감사 로그를 일반 수정/삭제 가능한 운영 테이블처럼 취급하지 않는다.
- 보안 검사를 통과시키기 위해 테스트를 삭제·skip하거나 검증을 약화하지 않는다.

## 3. 구현 기준

- 계층과 모듈 경계를 지키고 다른 모듈 테이블을 직접 수정하지 않는다.
- 공개 API 변경은 오류 코드, 권한, 멱등성, pagination, 하위 호환성을 검토한다.
- 상태 변경은 정의된 상태 머신을 사용하고 행위자·사유·시각을 감사한다.
- 외부 부작용은 가능한 한 outbox/worker로 처리하며 소비자는 idempotent해야 한다.
- 시간은 UTC 저장, IANA 센터 시간대 표시를 사용한다.
- 로그는 구조화하되 최소 PII만 포함한다.
- 새 환경 변수는 예시와 운영 문서에 설명하고 비밀값 기본치를 커밋하지 않는다.

## 4. 변경 시 동반 작업

| 변경 | 반드시 갱신/검토 |
|---|---|
| 엔티티/컬럼/제약 | `02_Database`, migration, integration test |
| Endpoint/오류 코드 | `03_API`, contract/E2E test |
| 화면/사용 흐름 | `04_UI_UX`, 접근성 test |
| 인증/권한/개인정보 | `05_Security`, threat case, security test |
| 제품 원칙/기술 결정 | `00_Project_Principles`, `08_Decision_Log` |
| 사용자에게 보이는 릴리스 변경 | `09_Change_Log` |
| 완료된 작업 | `07_Activity_Log`, 관련 Epic |

## 5. 테스트 규칙

- 정상 경로만 테스트하지 말고 무권한, 다른 센터, 만료, 재사용, 동시성, 재시도를 포함한다.
- 인증/권한 관련 수정에는 최소 한 개의 부정 테스트를 추가한다.
- 버그 수정은 먼저 재현 테스트를 만들고 수정 후 회귀를 검증한다.
- 시간 의존 코드는 주입 가능한 clock을 사용한다.
- 소셜/이메일 공급자는 로컬 테스트에서 실제 운영 계정이나 비밀값을 사용하지 않는다.

## 6. 데이터베이스 변경

- migration은 순방향 호환을 우선하며 Expand → Migrate → Contract로 나눈다.
- 대량 backfill은 배치, 재시작 가능, 관측 가능하게 설계한다.
- 새 센터 테이블에는 `center_id`, FK, 복합 인덱스와 격리 테스트를 포함한다.
- destructive migration, 데이터 삭제, 복구 불가능한 작업은 명시적 승인과 백업/롤백 계획 없이 수행하지 않는다.

## 7. 완료 보고

완료 시 변경 파일, 핵심 결정, 수행한 검증, 남은 위험/미확정 항목을 간결히 보고한다. 실행하지 못한 테스트를 실행한 것처럼 말하지 않는다.
