# NICEPAY 카드사 심사 준비 요약 — NotebookLM 업로드용 (2026-10-30)

서비스: 모하빗(MWHABIT) — 센터(스튜디오·체육관) 수업 예약·수강권 판매 플랫폼. 저장소 `sonjw222/booking-app`. 이 요약은 `docs/payments/NICEPAY_CARD_REVIEW_FINAL_20261030.md` 의 압축본이며, 상세 근거·SQL 은 그 문서를 본다.

## 1. 한 문장 현황
코드·법적 문구·심사용 SQL 은 준비됐고 로컬 격리 환경에서 모두 검증했다. **운영 반영은 아직 하나도 하지 않았다**(결제 OFF, 주소 비공개, 심사 센터·계정 미생성). 카드사 심사 신청 전에 사용자의 승인·콘텐츠 작업·NICEPAY 계약 정보가 필요하다.

## 2. 결제 구조(사실)
- 신규 PG 는 NICEPAY(v3 결제창, MID/MerchantKey 방식). 과거 토스페이먼츠 거래의 조회·취소·환불 서버 기능은 유지, 신규 토스 결제는 불가.
- 결제는 이중으로 잠겨 있다: 코드 상수 `NICEPAY_CHECKOUT_ACTIVATED=false`(환경변수로 못 켬) + DB 게이트 `off`. 일반 회원은 직접결제(센터 현장 결제)만 가능.
- 승인은 서버만 한다: 결제창 인증 → 서버가 서명·금액·주문번호 검증 → 승인 API → DB 주문 `done` 일 때만 수강권 발급. 금액·상품은 항상 DB 주문 기준(브라우저 값은 신뢰하지 않음).
- 공식 문서(결제창 호출·승인·망취소, 2026-10-30 열람)의 서명 공식·성공 코드·인코딩과 구현이 일치. 보완 1건: GoodsName 40byte/euc-kr 제한을 지키도록 정리 로직 추가.

## 3. 심사 화면(홈페이지·법적 고지)
- 약관 제9조·환불 정책 4항·개인정보 처리위탁 표·사업자 정보를 실제 구현에 맞춤: 신규 온라인 결제는 NICEPAY(서비스 준비 상황에 따라 제공), 과거 토스페이먼츠 거래의 취소·환불은 계속 처리. 현재 제공하지 않는 카카오페이·토스페이 문구 제거. 환불 기간·조건·정산 구조는 변경 없음.
- 확인되지 않은 것은 쓰지 않음: NICEPAY 정식 상호, 위탁 범위·보유 기간, 계약 사실. 약관 시행일은 바꾸지 않음(법적 고지·공지 절차는 사용자 결정).
- 홈·`/products`: 상호·대표·사업자등록번호·통신판매업 신고번호·고객센터·정책 링크 표시. 사업장 주소는 플래그(`NEXT_PUBLIC_SHOW_BUSINESS_ADDRESS_IN_FOOTER`) 기본 OFF — 공개 시점은 사용자 승인. (`/legal/business` 는 기존부터 주소를 항상 표시.)
- 상품 표시: 이름·가격·횟수·이용기간(사전예약기간·서비스 제공기간 날짜)·환불정책 링크.

## 4. 공개 상품 문제
- 만료 고정일 상품은 자동 숨김(10/31 이후). 그 뒤 공개 목록에는 "테스트"(100원, 만료일 없음) 1건만 남는다.
- 비공개: 센터 관리자 화면 "판매 정지"(권장) 또는 제안 SQL(미실행). **숨기면 공개 목록이 비므로 실제 판매 상품 등록이 먼저 필요**(심사 센터 상품은 심사관에게만 보임).

## 5. 심사 전용 센터·계정(미생성)
- 심사 센터는 일반 회원에게 보이지 않고, 전용 권한 계정만 접근(P2/P2b 적용·검증 완료). 운영 센터 상품으로는 심사관도 결제 불가.
- 제안 상품: "1/5/10회 이용권 (심사용)" 15,000/60,000/110,000원, 이용기간 30/60/90일, 사전예약 0일 — NICEPAY 기준(사전예약 ≤60일, 제공기간 ≤1년) 충족, 소개·설명에 "심사용 거래, 실제 수업·서비스 제공 없음" 명시.
- 실행 순서(운영 SQL Editor, 승인 후): 사전 점검(읽기) → 센터·상품 생성 → 심사 전용 계정 지정 → 검증(읽기) → 심사 종료 시 원복(권한 해제·게이트 off·센터 비공개, 데이터 삭제 없음).
- 심사 전용 별도 계정 권장(운영 계정에 지정하면 그 계정의 회원 화면에서 운영 센터가 숨음).

## 6. 검증(로컬 격리, 실제 NICEPAY 호출 0건)
단위·통합 테스트 전체 통과, 프로덕션 빌드 성공, 격리 브라우저 QA(모의 결제창·모의 승인) 통과: 심사관 로그인 → 심사 센터 상품 선택 → 결제 화면 → 결제창 → 완료(데스크톱·모바일 라이트), 게이트 off·일반 회원 비노출, 위변조·금액 불일치·중복·동시 승인 방어, 닫기/실패/망취소 경로, 법적 고지 4개 페이지·홈·상품 목록 화면(주소 미표시). 운영·DEV SQL 실행·push·배포 없음.

## 7. 남은 항목(우선순위)
1. 실제 판매 상품 등록 + "테스트" 비공개. 2. 사업장 주소 공개 승인(Vercel 플래그 + 재배포). 3. NICEPAY 계약 정보(정식 상호·위탁 범위/보유기간·MID/MerchantKey·허용 호스트·요청 Amt 패딩·앱 WebView 파라미터). 4. 법적 고지 시행일·공지 결정. 5. P3 실행 승인(이름·가격·기간·계정 이메일 확정). 6. 결제 활성화 승인(환경변수 → 코드 상수 PR → 게이트 reviewer, 심사 기간만). 7. 심사 종료 후 원복.

## 8. 용어
P2/P2b: 심사 센터 분리·결제 게이트 심사관 판별 SQL(운영 적용 완료). P3: 심사 센터·상품 생성과 심사관 지정(미실행). 게이트: `nicepay_checkout_gate.mode`(off/reviewer/public). 심사관: `accounts.nicepay_review_access=true` 계정.
