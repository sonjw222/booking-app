## 2. 비회원 공개 상품 — 외부 센터 소유권 및 심사요건 확인

2026-10-30 Production DB에서 `public.fetch_public_storefront_products(NULL::uuid)`를 **읽기 전용** 조회한 결과는 다음 3건이었다. `products` 테이블의 `is_active/is_on_sale`만으로 공개 상품을 계산하면 안 된다. 내부 센터·가시성·RPC 조건이 다르기 때문이다.

| 상품(공개 RPC) | 센터 | 현재 설명 | 조치 제안 |
| --- | --- | --- | --- |
| `피겨화 대여` (6,000원부터) | A10TION 피겨팀 | 품목 `goods`, 종료일 2026-10-30 | 10/31 이후에도 공개되는지 재조회. 수강권 자체를 대표할 수 없음 |
| `테스트` (100원) | A10TION 피겨팀 | `pass`, 설명 없음, `expiry_mode=none` | **센터 소유자의 결정이 필요**. 모하빗이 직접 판매 중단하거나 SQL로 변경 금지 |
| `10월 어텐션 파티 수강권` (50,000원) | A10TION 피겨팀 | `pass`, 종료일 2026-10-30 | 종료 뒤 자동 숨김 확인, 신규 실판매 상품 필요 |

**중요 정정(2026-10-30 사용자 확인)**: **A10TION 피겨팀은 실제 외부 센터이며, 모하빗 운영자는 그 센터의 관리·상품 수정 권한이 없다.** 앞서 모하빗 운영자가 해당 센터 상품을 직접 수정할 수 있다는 안내는 잘못되었다. A10TION의 기존 상품은 **해당 센터 소유자 동의 및 적법한 권한 없이는 절대 변경하지 않는다.**

**발견**: 비로그인 공개 상품 목록은 심사 관점에서 설명·제공기간이 불명확한 상품만 남을 가능성이 있다. 이것이 반드시 카드사 심사 반려 사유인지, 심사관 전용 센터 3종만으로 충분한지는 **NICEPAY 영업·심사팀의 서면 확인 전 단정하지 않는다.**

**대책 (실제 비즈니스 판단 필요)**

1. **먼저 NICEPAY 영업·심사팀에 확인**: 심사관 전용 계정·수강권 3종만으로 접수 가능한지, 일반 공개 실판매 상품이 추가로 필수인지 명확하게 받는다.
2. 일반 실판매 상품이 필요하다면 **자발적 제휴 센터의 담당자가 자기 관리 권한으로** 실제 판매 가능한 상품을 공개 등록하도록 협의한다. 사용자에게 A10TION 센터 관리자 권한을 요구하지 않는다.
3. 외부 센터의 `테스트`(100원)는 **A10TION 담당자가 직접 판매 중단 여부를 결정**하도록 안내할 수 있으나, 모하빗 운영자·자동화·SQL로 임의 변경하지 않는다.
4. 사용 가능한 실판매 상품은 실제 `/products` 화면과 공개 RPC에서 재검증한다. 상품 정보·가격·서비스 제공기간은 센터가 확인한 사실만 게시한다.
5. 심사관 전용 상품(1/5/10회)과 **일반 공개 실판매 상품은 구별**한다. 어느 쪽이 심사에 필요한지는 NICEPAY 답변으로 최종 확정한다.

### 제출 직전 읽기 전용 DB 확인

```sql
SELECT mode FROM public.nicepay_checkout_gate WHERE id = true;
SELECT count(*) AS review_accounts FROM public.accounts WHERE nicepay_review_access = true;
SELECT count(*) AS review_centers FROM public.centers WHERE is_nicepay_review = true;
SELECT p.name, p.center_name, p.price, p.product_kind
FROM public.fetch_public_storefront_products(NULL::uuid) AS p
ORDER BY p.center_name, p.name;
```
> 위 SQL은 전부 **SELECT만 수행**한다. 어떤 설정도 변경하지 않는다. 이 검증을 Production에서 자동 실행하도록 연결하지 않는다.
