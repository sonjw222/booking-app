## 통합 회귀 (이번에 실제 실행, 격리 DB + 실제 JWT + 격리 브라우저)
1. 주문→관리자 발급→회원 수강권→예약→취소→복구: 격리 DB(발급 권한: 직원·회원 거절, 중복·동시 발급 1건, `already_done` 멱등, 예약 2회→취소 3회 복구, 중복 예약 거절, 타 계정 취소 거절, 대여 상품 함께 예약 시 상품 1회·수강권 1회 차감→취소 시 둘 다 복구) + 격리 브라우저(예약→DB 차감→UI 취소→복구).
2. 마지막 좌석 경쟁(동시 3건 → 확정 1·대기 2, 대기자 미차감)→앞 예약 취소→순서 승격(승격 시 차감)→최종 취소 후 전부 복구. 기간 무제한 수강권 대기자 승격 누락(F21) 재현·수정.
3. 발급/자기취소 경쟁(4회 반복: 둘 중 하나만 성립), F18 동시 회수, F19 중복 휴면 복구, 일일·프라이빗 한도 경쟁.
4. 쿠폰 후보/서버 자격 일치, 후기 작성·수정·답변·포인트(RPC 수준). **후기 작성/사진 UI 흐름은 브라우저로 열지 않음**.
5. 제한 직원의 정상 조회와 변경 거부(설정, 발급, 회수, 휴면, 후기), 운영 설정 읽기 전용 화면.
6. 매출 두 모드 표시(격리 브라우저)·합계 보존(PGlite), 링크 이동 후 로그아웃.

## 환경 한계·불확실성
- 격리 DB는 저장소 SQL로 재구성한 것이다. 운영에 어떤 draft 마이그레이션이 적용됐는지는 이 저장소만으로 알 수 없다. 재구성 중 확인된 차이: `orders.verified` 컬럼을 만드는 마이그레이션이 저장소에 없음(격리 DB에서만 보정, `tests/rls-real/05_shims.sql`), `fix_order_point_lifecycle.sql`(취소 주문 재발급 차단)을 체인에 추가해야 운영 감사 결과와 일치함.
- 시간은 시드 날짜로 제어했고 전역 시계는 바꾸지 않았다. 알림·결제·푸시 외부 전송 없음.
- 미실행: 실기기(iOS/Android), 실제 PostgreSQL 운영 환경, 운영 cron, 외부 푸시, 운영 브라우저, WebKit 실기기. mock Playwright 전체는 4개 프로젝트에서 실행했으나 격리 브라우저 스펙은 Chromium(데스크톱+모바일)만 실행했다.
- `npm run lint`는 설정 파일 부재로 기존대로 실패 → `scripts/lint/check.mjs`(신규 0건)로 대체. tsc 오류 49건은 main과 동일한 기존 기준선. 빌드는 이 워크트리에 `.env.local`이 없어 더미 공개 env로 실행.

## 정책 결정이 필요한 항목 (수정을 멈추지 않고 모아 둠)
