# 관리자 센터 페이지 조회 (승인 전 Draft)

SQL 필요: YES. 운영/DEV SQL 실행 및 배포는 하지 않았다.

`NEXT_PUBLIC_ADMIN_CENTER_PAGINATION`이 `true`인 빌드만 새 RPC를 사용한다. 기본값은 기존 관리자 RPC이며, 서버 권한 오류나 누락된 RPC를 기존 함수 재시도로 숨기지 않는다. 현재 승인 없이 운영 서버 조회 개선이 활성화되지는 않는다.

변경: SQL이 검색한 결과를 created_at DESC, id DESC로 정렬하고 커서 이후 최대 31개만 반환한다. 화면은 30개를 표시하고 31번째는 다음 페이지 존재 확인에 쓴다. 검색 300ms 대기, 요청 역전 무시, 탭/검색 유지, 승인/반려 후 새 첫 페이지 조회. 기존 전화/사업자번호 구분 기호 검색을 유지한다. 타임스탬프가 같은 1,000개 합성 행도 중복/누락 없이 34번의 조회로 모두 확인했다.

## 적용 순서 (각 외부 작업 별도 승인)

1. 지정한 비운영 Supabase에서 migration `supabase/migrations/20261011113106_admin_center_page_draft.sql`을 소유자 postgres로 검토·적용.
2. `verify_admin_center_page_20261011.sql` 메타데이터 확인. 비운영 일반 계정/익명/플랫폼 관리자에서 문서 하단 권한 및 페이지 테스트 확인.
3. 비운영 빌드에만 `NEXT_PUBLIC_ADMIN_CENTER_PAGINATION=true` 설정하고 검색/더 보기/승인·반려 후 갱신 QA.
4. 별도 운영 SQL 승인 후 같은 migration과 verify. 별도 merge/production 배포 승인 전 기본값 유지.
5. 운영 활성화는 SQL 검증 후 새 빌드에 플래그=true 적용. SQL 파일만 적용하면 현재 앱에 영향 없음.

롤백: 먼저 플래그를 끄고 앱 재빌드·검증, 이후 별도 승인으로 `rollback_admin_center_page_20261011.sql`. 테이블/행/RLS 정책은 변경하지 않는다.

## 검증과 한계

PGlite 테스트: 익명/일반 사용자/NULL 관리자 거부, 잘못된 입력 거부, 재실행, 동일 시간 커서, 문자 `%_` 리터럴 검색, 대표자·전화·사업자번호 검색, 다른 상태 제외, 데이터 보존 롤백. 서버 활성화 합성 1,000행 첫 응답은 전체 1,000행 대신 31행 (행 수 96.9% 감소). 실제 네트워크 바이트/운영 SQL 시간 개선 수치는 아니다. 검색은 조건 검사/정렬을 위해 여러 행을 읽을 수 있고 아직 인덱스를 추가하지 않았다. 따라서 DB 실행시간 개선을 주장하지 않는다.

비활성 상태에서 호환 모드는 기존 전체 목록을 받아 클라이언트에서 페이지를 나눈다. 더 보기 시 기존 RPC를 다시 호출한다. SQL 승인 후 플래그 활성화해야 서버 응답 크기가 줄어든다.

현재 SQL 테스트는 비운영 합성 스키마이며 실제 Supabase 권한/인덱스/데이터 크기 검증을 대신하지 않는다. 라이브 테스트에 사용할 비운영 프로젝트 지정은 사용자 답변 대기.
