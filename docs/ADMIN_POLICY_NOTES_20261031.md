# 정책 결정 대기 항목 정리 (#248) — 2026-10-31

**이 문서는 정책을 바꾸지 않는다.** 결정에 필요한 대상·기존 데이터 영향·권장안만 정리한다. 결정 후 별도 구현.

## 1. 프라이빗 수업 시간 단위 범위 (F04)
- **현재 동작**: `center_settings.private_slot_unit`(`hour|30min|20min|15min|10min|5min`, 기본 `30min`)이 스키마에만 있고 코드 참조가 없다. 수업 등록 시간 입력은 5분 단위로 열려 있어 프라이빗(1:1) 수업도 아무 시각(예: 10:15)에 만들고 예약할 수 있다. 안내 문구만 있고 서버·화면 어디서도 강제하지 않는다.
- **적용 대상**: 프라이빗(`classes.class_format='private'`) 수업의 시작 시각 정렬 규칙. 그룹 수업은 해당 없음.
- **기존 데이터 영향**(운영 읽기 전용 집계, 2026-10-31): 프라이빗 수업 2건(둘 다 미래), 그중 1건이 10·30분 단위가 아닌 시각. 신규 규칙을 소급 적용하면 이 1건이 위반이 되므로 **소급 차단 금지** 규칙이 필요하다.
- **선택지**: (a) 단위를 제안 값으로만 둠(현재와 같음) (b) 신규 프라이빗 생성·시간 변경 때만 시작 시각 정렬을 검증 (c) 예약 단계에서도 요구(기존 비정렬 수업을 예외 처리해야 함).
- **권장안**: (b). 기존 수업은 그대로 두고, 새로 만들 때만 센터 설정(`private_slot_unit`)에 맞춰 검증. 구현 전 센터별 기본값(현재 `30min`)이 실제 운영 의도와 맞는지 먼저 확인.

## 2. 후기 삭제 후 재작성 시 보상(포인트)
- **현재 동작**: 센터·회원당 후기 1건(유니크). 작성 시 통합 포인트 원장에 보상 1회(`write_review` RPC, 사진 유무 별도). 수정은 후기 ID·답글·보상 이력을 보존한다. 후기를 **삭제하면 행이 사라지므로 같은 회원이 다시 작성할 때 보상이 다시 지급**될 수 있다(격리 DB 확인).
- **적용 대상**: 후기를 삭제한 뒤 같은 센터에 다시 쓰는 회원(보상 포인트 어뷰징 가능성). 수정·답변은 해당 없음.
- **기존 데이터 영향**(운영 읽기 전용 집계): 후기 1건(답글 있음) — 재작성으로 중복 지급된 사례가 있을 가능성은 사실상 없다. 레거시 포인트 이관(`proposed_migrate_legacy_review_points_20261022.sql`)은 별개 항목이며 실행 금지 상태 그대로.
- **선택지**: (a) 현행 유지(삭제 후 재작성도 보상) (b) 센터·회원당 보상은 평생 1회(삭제 후 재작성은 보상 없음, 원장 기록으로 판정) (c) 일정 기간(예: 삭제 후 N일) 내 재작성은 보상 없음.
- **권장안**: (b). 원장에 이미 있는 후기 보상 이력으로 판정하면 신규 컬럼이 필요 없고 기존 지급분에는 영향이 없다. 정책 확정 뒤 SQL 이 필요하면 별도 승인 절차.

(참고) "후기 답변 전용 권한 키"는 `facility.review.reply` 가 이미 카탈로그에 있고, 이 키가 없는 직원은 답변 버튼이 없고 서버도 거부한다(관리자 QA 매트릭스 확인) — 별도 결정 불필요.
