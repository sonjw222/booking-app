# 취소 전 안내 수정

개발 DB의 실제 cancel_reservation/calc_deadline 정의를 읽어 규칙을 확인했다. 개별 수업 취소마감 우선, 센터 calc_deadline, 예약 후 10분 유예(수업 시작 상한), 당일 예약의 same_day_change 예외, allow_cancel=false, 마감 후 deduct_on_late_cancel을 사전 안내에 반영한다. 두 회원 화면이 같은 조회/계산 helper를 사용한다. 마감 전은 무료/차감 없음, 마감 후 차감 설정이면 사용 횟수 복원 안 됨, 차감 설정이 꺼져 있으면 취소 불가를 안내한다.

조회는 로그인 사용자 RLS로 예약·수업·센터 설정을 읽고 기존 calc_deadline RPC만 사용한다. SQL 필요 NO. 새 함수/권한/RLS/데이터 변경 없음. 설정 조회가 실패하거나 보이지 않으면 무료라고 추정하지 않고 오류를 알린다. 설정 행이 없는 센터는 이번 사전 안내에서 확인 실패를 표시하며, 그 경우 별도 정확한 서버 미리보기 경로가 필요하다.

브라우저 시계와 표시 후 시간 경과에 의해 실제 결과가 달라질 수 있어 확정 시 cancel_reservation이 권한/마감/차감을 다시 검사하며 그 결과를 표시한다. 서버 최종 취소 규칙은 변경하지 않는다. 사전 안내는 취소 처리나 차감 확정을 하지 않는다.

단위 테스트: 마감 후 차감/거부, 정확히 10분/초과/수업 시작, KST 당일 예외/전날 예약 제외, allow_cancel=false, 잘못된 시각. 신규 E2E의 실제 성공 여부는 후속 CI에서 확인한다.
